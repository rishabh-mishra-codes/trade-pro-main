# Deploying TradePro: Render (backend) + Vercel (frontend)

Order matters: DB -> backend -> frontend -> back to backend to set CORS.

## 0. Files added by this change
- `backend/Dockerfile`, `backend/.dockerignore`: Render has no native Java runtime, so it builds via Docker.
- `render.yaml`: Render Blueprint (service + env var names).
- `vercel.json`: Vite build + SPA rewrite (needed for react-router deep links like /portfolio).

## 1. One required code change: health endpoint
`SecurityConfig` permits `/actuator/health`, but `backend/pom.xml` has no actuator dependency, so it 404s.
Add inside `<dependencies>`:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

(Or delete `healthCheckPath` from `render.yaml`.)

## 2. Database (Neon)
Create a project at neon.tech. Copy host, db, user, password. Tables are auto-created (`ddl-auto=update`).
- `DB_URL` = `jdbc:postgresql://<host>/<db>?sslmode=require`
- `DB_USERNAME`, `DB_PASSWORD`

## 3. Backend on Render
1. Push this repo to GitHub.
2. Render dashboard -> New -> Blueprint -> pick the repo (reads `render.yaml`).
   Or New -> Web Service -> Runtime Docker, Root Directory `backend`.
3. Fill the `sync: false` env vars:

| Variable | Value |
|---|---|
| DB_URL / DB_USERNAME / DB_PASSWORD | from Neon |
| JWT_SECRET | auto-generated by blueprint (>= 32 chars) |
| CORS_ORIGINS | placeholder now, set to Vercel URL in step 5 |
| FRONTEND_URL | same Vercel URL (used in reset-password links) |
| RAZORPAY_KEY_ID / RAZORPAY_KEY_SECRET | Razorpay dashboard (use test keys) |
| TWELVE_DATA_API_KEY | twelvedata.com |
| GEMINI_API_KEY | Google AI Studio |
| EXPOSE_RESET_TOKEN | `false` in prod (with MAIL_ENABLED=false users cannot reset passwords; enable SMTP below) |
| MAIL_ENABLED, MAIL_USERNAME, MAIL_PASSWORD | optional; Gmail needs an App Password |

4. After deploy, note the URL, e.g. `https://tradepro-backend.onrender.com`. Test `/actuator/health`.

Free-tier note: the service sleeps after ~15 min idle (first request ~30-60 s). The price-alert and stop-loss schedulers do not run while it sleeps.

## 4. Frontend on Vercel
1. vercel.com -> Add New -> Project -> import the repo (root directory = repo root; Vite is auto-detected).
2. Environment Variables (they are baked in at build time, so redeploy after changing):

| Variable | Value |
|---|---|
| VITE_API_URL | `https://tradepro-backend.onrender.com/api` |
| VITE_TWELVE_DATA_API_KEY | your Twelve Data key (public in the bundle; use a free-tier key) |
| VITE_RAZORPAY_KEY_ID | Razorpay public key id |

3. Deploy. Note the URL, e.g. `https://tradepro.vercel.app`.

## 5. Close the loop
In Render, set `CORS_ORIGINS=https://tradepro.vercel.app` and `FRONTEND_URL=https://tradepro.vercel.app` (no trailing slash, exact origin). Render redeploys automatically. For preview deployments, add them comma-separated.

## 6. Smoke test
Open the Vercel URL, register, log in, buy a stock, add funds with a Razorpay test card.
If the browser shows a CORS error, `CORS_ORIGINS` does not exactly match the origin. If requests go to localhost, `VITE_API_URL` was not set before the build.

## Security: do before going public
- The README says demo Razorpay/DB/Gemini keys are pre-filled in `.example` templates and `.env.example` contains a Razorpay key. Rotate any key that was ever committed.
- Keep `EXPOSE_RESET_TOKEN=false` in production; otherwise anyone can reset any account's password via the API response.
